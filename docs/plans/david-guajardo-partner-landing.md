## Problem Statement

`/early-access` is the correct **general** waitlist for AstroLink. Chris Sembroski is the featured hero there; other roster experts (including David Guajardo) appear only as small portrait tiles in a horizontal strip.

David needs a **shareable URL he owns** — something he can drop in bio, posts, and DMs where *his* audience lands on *his* story, not Chris’s. Without that, David’s distribution either sends traffic to a page that centers another expert, or he doesn’t share at all.

## Demand Evidence

| Signal | What it means |
|--------|----------------|
| User question: “should we create a public page for him to share?” | Explicit partner GTM need — distribution through roster experts is part of launch strategy |
| Existing `?ref=` taxonomy + admin referrer dashboard | Infrastructure already values attributed signups; partner pages are a UX layer on the same data model |
| Chris featured on `/early-access` | Proof that “one expert as hero” converts better than roster strip alone — David deserves the same treatment for *his* traffic |

**Gap:** No behavioral proof yet that David’s followers convert. Treat v1 as a **distribution experiment**, not a platform bet.

## Status Quo

- **General public:** `https://<host>/early-access` (Chris hero + roster strip)
- **Attribution today:** `?ref=<campaign-id>` on `/early-access` (see `marketing-referrer-taxonomy.md`)
- **Waitlist mode:** `/experts` and `/` are blocked; only `/early-access`, `/privacy`, and admin ops routes are public
- **David today:** Listed in DB (per product context); appears in roster strip only; no owned landing

**Competitor / alternative:** David shares `/early-access?ref=expert-david-guajardo` — works for attribution, fails for narrative (Chris is still the hero).

## Target User & Narrowest Wedge

**Target user:** A follower of David Guajardo who already trusts *him* and clicks a link from his social/bio/newsletter.

**Narrowest wedge (v1):** One URL per roster expert that:

1. Features **that expert** (portrait + intro video if available) in the Chris-style hero panel
2. Uses personalized headline/subcopy (“Join the waitlist to book a live session with David Guajardo”)
3. Reuses the **same** single opt-in email form and `/api/early-access` pipeline
4. Auto-attributes signups with `ref=expert-<slug>` (e.g. `expert-david-guajardo`)

**Not in v1:** Booking, pricing, modalities, full `/experts/[slug]` profile, or a separate DB table.

## Constraints

- `APP_MODE=waitlist` must remain locked down — new route must be added to waitlist allowlist (`waitlist-routes.ts`)
- No PII in analytics; reuse existing Vercel custom events where possible
- David’s slug, bio, video, and portrait must come from existing `mentors` row (`getMentorBySlug` already exists)
- Do not reopen full app surfaces (`/experts`, `/booking`) in waitlist mode
- **Minimal diff:** reuse waitlist components; no refactor of `/early-access`

## Premises

1. **Premise:** David will actively share a dedicated link if it feels like *his* page.  
   *Falsified if:* he still prefers generic `/early-access` after v1 ships.

2. **Premise:** Personalized hero beats `?ref=` alone for influencer conversion.  
   *Falsified if:* `expert-david-guajardo` signups from `/early-access?ref=...` match or beat `/join/david-guajardo` in A/B window.

3. **Premise:** A parameterized `/join/[slug]` route is not over-engineering — more roster experts will want the same.  
   *Falsified if:* only David ever gets a page (then a static route would have been enough).

## Approaches Considered

### Approach A: Ref-only (no new page)

`/early-access?ref=expert-david-guajardo`

| Pros | Cons |
|------|------|
| Zero code | Chris remains hero — weak partner story |
| Attribution works today | David unlikely to promote “someone else’s” page |
| | Cannot personalize OG meta for David’s shares |

**Verdict:** Good fallback, not a partner product.

### Approach B: Dedicated static page `/join/david-guajardo`

Hardcoded David content + reused form.

| Pros | Cons |
|------|------|
| Smallest possible scope | Copy-paste for next expert |
| Fast | Content drift vs DB |

**Verdict:** Only if you are certain David is the *only* partner landing ever.

### Approach C: Parameterized partner landing `/join/[slug]` (recommended)

Dynamic page backed by `getMentorBySlug`, reusing waitlist UI primitives.

| Pros | Cons |
|------|------|
| David-first, scales to roster | ~6–8 files touched |
| DB-driven bio/video/portrait | Must handle missing slug → 404 |
| Clean share URL for David | Needs one small form prop for default `ref` |
| Waitlist-safe with allowlist tweak | |

**Verdict:** Best wedge for partnership distribution without opening full directory.

## Recommended Approach

**Build Approach C:** `/join/[slug]` partner waitlist landings.

### URL & attribution

| Item | Value |
|------|--------|
| Public URL | `https://<host>/join/david-guajardo` |
| Stored referrer | `expert-david-guajardo` (add row to `marketing-referrer-taxonomy.md`) |
| Redirect | Invalid/unlisted slug → `notFound()` (404), not redirect to generic waitlist |

### Page layout (mirror early-access, expert-swapped)

```
┌─────────────────────────────────────────────────────────────┐
│ HEADER: AstroLink logo · Back link → /early-access (subtle) │
├─────────────────────────────────────────────────────────────┤
│ LEFT: Headline + subcopy featuring David                    │
│       Signup form (same as waitlist)                        │
├─────────────────────────────────────────────────────────────┤
│ RIGHT (desktop) / ABOVE STRIP (mobile):                     │
│       David portrait + intro video (ExpertIntroMedia)       │
│       Name, role, employer                                  │
├─────────────────────────────────────────────────────────────┤
│ Optional: slim “Also on AstroLink” strip (2–3 faces, no Chris hero) │
├─────────────────────────────────────────────────────────────┤
│ FOOTER: © · Privacy                                         │
└─────────────────────────────────────────────────────────────┘
```

**Copy pattern:**

- Headline: “Book a live 1:1 session with [David Guajardo].”
- Subcopy: Pull role/employer from DB; one line on what attendees get (waitlist, not booking yet).

### OG / share cards

`generateMetadata` per slug: title `Early access · David Guajardo · AstroLink`, description from bio truncate, image from `imageUrl`.

## Success Criteria

| Metric | Target (2 weeks after David shares) |
|--------|-------------------------------------|
| Signups with `ref=expert-david-guajardo` | ≥ 10 (adjust to David’s audience size) |
| `waitlist_intro_play` on David’s page | ≥ 20% of pageviews (if video exists) |
| David actually shared the link | Yes, in ≥ 1 channel (bio, post, or newsletter) |
| Zero leakage | `/experts`, `/booking`, `/` still redirect in waitlist mode |

If yes, ship `/join/david-guajardo` and give him the link the same day — then check admin dashboard for `expert-david-guajardo` signups within 7 days.

- You separated “general public waitlist” from “expert distribution” — that’s the right instinct; conflating them undervalues roster partners.
- You asked for minimal file touch — good discipline for waitlist phase; Approach C satisfies that without a one-off hack.
- You’re thinking about David’s followers, not just AstroLink’s homepage — distribution through experts is your wedge, not more landing page polish.
